# DCT Learn — Backend guide

How the API in `server/` is organised and the rules every change follows. The contract is
[`API-CONTRACT.md`](API-CONTRACT.md); the data is [`SEED.md`](SEED.md).

## Stack

Bun · Express 5 · Better Auth (cookie sessions) · Drizzle 0.45 + PostgreSQL (postgres.js) · Zod 4 ·
pino · Handlebars e-mails (Mailpit in dev, SES deployed) · local disk or S3 storage · Postgres-backed job
queue · OpenAPI generated from the routes (`/api/docs`).

## Layout (layer-first, like our other Express projects)

```
shared/
  roles.ts, enums.ts            contract §0.1
  schemas/<area>.ts             Zod request + response shapes (the DTOs) — shared with the client
server/
  index.ts                      listen, start jobs, graceful stop
  app.ts                        buildApp(): middleware order, routers, 404, errors
  config/env.ts                 the only reader of process.env (contract §9.9)
  auth/                         Better Auth config + hooks (sign-up rule, sessions, lockout)
  db/
    connection.ts, columns.ts   one postgres.js handle; shared column helpers (i18n jsonb, timestamps)
    schema/<area>.ts            Drizzle tables, one file per area (collected by glob, no barrel)
    migrations/                 generated by `bun run db:generate` only
    seed/data.ts                SEED.md as data
    seed/slices/<area>.seed.ts  composable seed slices (dev seed + test fixtures)
  routes/<area>.routes.ts       URL + auth middleware + schemas → controller (via `route()`)
  controllers/<area>.controller.ts  reads ctx (viewer, params, body), calls services, returns data
  services/<area>/*.service.ts  business rules, transactions, ownership, audit — no Express
  services/seams/               registries other areas plug into (see below)
  services/providers/           Zoom / AI / matching providers (stubs until configured)
  middleware/                   auth, microsite scope, rate limits, uploads, security, errors
  jobs/<area>.job.ts            defineJob / defineSchedule; jobs/index.ts imports them all
  lib/                          errors, route(), audit, if-match, sanitize, clock, storage, logger
  utils/                        csv, tokens, file signatures
  templates/<name>.hbs          e-mails (first line `{{!-- subject: … --}}`)
  __tests__/<area>/*.test.ts    bun test + supertest against a real test database
```

**Layer rules**
- `routes` only wire: path, the contract's **Auth:** line as middleware, request/response schemas.
- `controllers` stay thin: no SQL, no business rules.
- `services` never see `req`/`res`. Missing or foreign records → `notFound()` (404, never 403).
  Every "Audit: yes" action calls `recordAudit(tx, …)` inside the same transaction.
- Responses are checked against their schema in dev/test (`route()`), so an undocumented field fails tests.

## Access (contract §0.3)

| Term | Use |
|---|---|
| `public` | no middleware |
| `signed-in` | `requireAuth` (401 · 403 `email_not_verified` / `account_disabled`) |
| `role(x)` | `requireRole('x', …)` |
| `member(p)` | `requireMember` (learner + membership + live; sub admin of p and admin may view) — sets `res.locals.microsite` |
| `sub_admin(p)` | `requireSubAdmin` |
| feature flags | `requireFeature('mentoring' \| 'competition' \| 'ai')` after the microsite middleware → 404 `feature_off` |
| **own** / **assigned** | checked in the service; answer 404 |
| ifMatch | `assertIfMatch(row.updatedAt, body.ifMatch)` → 409 |
| Sanitise | `sanitizeRich` / `sanitizeEmbed` / `sanitizeText` on save |

Rate limits: `authLimiter` (10/min/IP), `publicFormLimiter` (5/min/IP), `userWriteLimiter`
(30/min/user: invitations, imports, uploads), global 120/min.

## Seams (how areas plug into each other without editing shared files)

| Seam | File | Who registers |
|---|---|---|
| P52 hub tabs | `services/seams/hub.registry.ts` `registerHubTab(tab, …)` | learning (courses), content (workshops, resources, ai_*), mentoring (mentors) |
| P14 dashboard sections | `services/seams/dashboard.registry.ts` `registerDashboardSection(key, …)` | content (resources, events, surveys), mentoring, competition |
| P35 KPIs | `registerMicrositeKpi('pendingResources', …)` | content |
| Action plans | `services/seams/action-plan.seam.ts` `setActionPlanReader`, `onActionPlanSaved` | learning implements; competition reads/locks |
| Course completion | `services/seams/course-completion.seam.ts` `setCompleteCourse` | learning implements; achievements (external certs) calls |
| Points | `services/catalog/points.service.ts` `awardPoints`, `pointsTotal`, `leaderboard` | everyone |
| Course cards | `services/catalog/course-card.service.ts` | everyone |
| Membership join | `onMembershipJoin(hook)` | any area needing per-member setup |
| Invitation accepted | `onInvitationAccepted(hook)` | mentoring (mentor profile), competition (judge roster) |
| P47 user detail | `registerUserDetailSection(fn)` | achievements (externalCertificates), mentoring (growLogsSummary) |
| P60 translations | `registerTranslatable({ entity, table, id, fields })` | every area with `{en, ar}` columns |
| Jobs | `defineJob`, `defineSchedule`, `enqueue(…, { tx })`, `queueEmail` | everyone |
| Providers | `videoProvider()`, `matchProvider()`, `insightsProvider()` | stubs: Zoom/AI off → 503 `feature_off`; matching rule-based |

Registrations live in `server/registrations/<area>.ts` (imported once by `registrations/index.ts`).

## Tests

- `bun test` uses `TEST_DATABASE_URL` (must contain "test"); the preload rebuilds the schema from
  `server/db/schema/*.ts` once per run (drizzle-kit push), then each file calls `freshBase()`.
- Sign in through the real route: `await as(E.saeed)`; signed out: `anon()`.
- Every endpoint: happy path parsed with its response schema · `expectDenied` for every role not
  allowed · other users' records 404 · invalid input 422 · its §9.1 / §9.4 rules.
- E-mails: `lastMailTo(email, template)` (delivers queued jobs into the in-memory outbox).
- Clock: business time is `now()` from `lib/clock.ts`, pinned to SEED today (2026-10-06 09:00 UTC).
